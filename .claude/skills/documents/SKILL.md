# 简历 DOCX 制作与检查

## 事实红线（最高优先级）

- 只能使用候选人已提供的事实：公司、机构、项目、职位、时间、学历、证书、奖项、数字。
- 不得虚构或擅改经历、时间、数据、头衔。原文没有的量化内容，标出来让用户自己填，不要代填。
- 改写只允许调整措辞、顺序和关键词嵌入。

## 优先复用项目已有实现

本仓库已有 DOCX 生成代码，优先改它，不要另起一套：

- `src/lib/optimizeDocx.ts`
  - `buildResumeDocx(text: string): Promise<Blob>` —— 把简历纯文本排成 A4 的 .docx
  - `parseResumeText(text)` —— 把纯文本拆成「姓名 + 各板块」
- 依赖 `docx`（已在 `package.json` 里），按需动态 import，不要引入新依赖。

## 本机工具现状（写之前先复核，变了就更新这里）

- `python-docx`：**当前未安装**。需要它时先说明用途并等确认，不要擅自 `pip install`。
- LibreOffice (`soffice`)：**当前不在 PATH 中**，因此无法转 PDF 做视觉检查。
- 结论：默认走「项目内生成 + 结构检查」这条路，不要假设能转 PDF。

## 排版规范

- **ATS 兼容**：关键信息用普通文字段落承载，不要用文本框、图片或复杂表格；项目符号用真正的列表项，不要用字符模拟。
- **字体统一**：中文宋体（`eastAsia` 必须单独设，否则 Word 会拿西文字体渲染中文）。
- **字号**：姓名 16 磅居中；板块标题 12 磅加粗带下划线；正文 10.5 磅。
- **页面**：A4（11906 × 16839 twip），页边距约 1000 twip（≈1.76 cm），行距 1.25。
- **层级**：姓名 → 板块标题 → 经历表头（公司 · 职位 · 起止时间）→ 项目符号要点。
- **经历表头不能丢**：公司、职位、起止时间必须保留，改写时一字不改。
- **技能**：单独成段，用顿号分隔，不要塞成长句。
- **页数**：应届/实习简历 1 页，最多 2 页。

## 分页与溢出检查

1. 有 LibreOffice 时：`soffice --headless --convert-to pdf --outdir <目录> <文件.docx>`，再转页面图片肉眼看分页、溢出、错位。
2. 没有 LibreOffice 时（**本机现状**）：只做结构检查——页面尺寸、页边距、字号、字体、段落数，然后**明确告诉用户"分页未经视觉确认"**。
3. 无论哪种情况，都**不要声称"已保证刚好一页"**。最终分页由 Word 按内容长度决定，程序无法预知。

## 边界

- 不安装新依赖；确实需要时先说明用途并等确认。
- 不改简历原文里的事实性内容。
- 通用文档需求（非简历）不属于本 skill。
